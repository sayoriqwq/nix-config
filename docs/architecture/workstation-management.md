# 主工作站管理

本仓库的 Nix 声明与 lock 是受管环境期望状态的唯一真源，并按维护者选择复用到 nixbox 或 server。日常维护围绕声明更新、应用与验证展开；决定见 [ADR-0011](../adr/0011-declaration-led-workstation-management.md)，术语见 [CONTEXT.md](../../CONTEXT.md)，结构与拓扑见[整体架构](overview.md)。

## 稳定声明与日常使用

nix-config 决定受管资源应该是什么样；现场读回确认实际是什么样，历史记录解释过去的变化。声明、已应用 generation 与现场可以暂时不同，不能仅凭任一方宣称三者一致。

受管软件安装、版本更新和长期偏好默认通过声明维护。应用内临时试验可以产生偏移；决定长期保留时，将所选内容转入权威声明并验证，放弃时在授权范围内恢复。现场变化不自动升级为新的期望状态，发现偏移也不授权无人值守覆盖或整机激活。

具体资源须明确承诺安装需求、精确版本还是配置内容。采用已有 Homebrew 集成可以让安装需求由 Nix 唯一声明，但不提供 Nix 包同等的版本固定；原生命令链接不等于应用安装恢复，seed 只负责初始化。需要精确版本或长期设置重建时，优先使用可兑现这些保证的声明机制；原生自更新、应用同步等已有例外保持明确边界，调整需具体任务。

日常入口优先复用 nh，具体步骤见[日常 Nix 维护](../runbooks/daily-nix-maintenance.md)。薄包装可以固定参数、管理候选和展示结果，权威内容仍是 Git 中的声明与 lock，产物与回滚仍由 Nix 管理，不增加第二份清单、版本数据库或声明语言。普通维护遵循现有本地提交与验证流程，不要求 PR，日常使用不以 Agent 介入为前提。

遇到故障先诊断、修复或回滚；命令体验问题先改善入口，安装方式变更需要具体兼容性或恢复收益。保留 Nix 带来的可重建性，按实际收益删除多余抽象，不以覆盖率决定归属。本决定不批量迁入迁出已有软件。

应用会重新执行所选配置的激活动作，必须先检查影响范围与需保留的现场修改。只要求更新一个软件不等于授权整机激活；沿用 [AGENTS.md](../../AGENTS.md) 的真实机器授权条件。

## 选择同步

跨主机复用由维护者选择软件、配置与目标机器，并验证目标上的实际结果：

- 配置与使用意图一致，允许必要的平台适配及独立的软件版本；只有明确要求时才核实精确版本一致。
- 目标上未选中的状态及偏移保持原样；所选受管配置的后续长期变更继续进入声明。
- 各 Host 的用户文件、应用数据、登录态和凭据独立。数据同步是单独需求，有需要时优先使用软件提供的同步能力。

当前操作若无法实现选定配置与意图，或无法保留未选中状态，应说明限制；扩大范围由维护者决定。只修改一个 Software 的声明再应用整机 output，不足以证明影响仅限于该软件。

## 私有记录与跨项目使用

个人实际状态和变化证据使用 Macwarden 的现有 Observation / Transition 模型保存。主 checkout 内的 `.macwarden/` 是被 Git 忽略的私有 authority；它不进入 Flake、公开提交或其他 worktree。Macwarden 工具源码与 Skills 继续由独立工具项目维护。

Macwarden setup 保存该 authority 的绝对路径，因此从其他 cwd 执行也访问同一份记录；使用时通过 `macwarden path` 核实目标，不依当前项目目录另建记录库。模型、CLI 和 Skill 合同以 Macwarden 工具项目自身文档为准，本仓库不复制其实现。

是否捕获、何时捕获以及哪些信息有用，由维护者显式指定。Agent 不因服务更新、长期环境变化或疑似遗漏而自行触发捕获；普通项目依赖仍归项目管理。

显式请求后的 Recall/Capture Skills 按其合同查历史、核实现场和保存所选证据。这里不增加常驻监听、自动追赶声明或另一套审批流程；具体执行约束见 [AGENTS.md](../../AGENTS.md)。

## 历史与恢复

已有状态的补录由维护者安排采用哪些原始流程、何时进行、覆盖什么。authority 尚未有记录不构成缺陷，也不形成自动盘点任务。

原始流程中的可信操作和前后回读可以支持历史 Transition；本次现场检查只证明本次状态。没有可靠 Before 时保存独立 Observation，保留历史未知项；当前记录不替换原始历史，不从记录顺序推断机器现状。

配置恢复使用选定的已知可用声明与仍可获取的产物。运行环境回滚与 Git 声明恢复是不同动作，需检查下一次应用是否会再次部署失败变更；generation 不保证撤销 defaults、外部安装器及应用数据的全部副作用。未保存的现场变化不属于声明恢复范围，历史 Change 也不是配置全文或软件产物的备份。

## 当前能力边界

以上约定确定使用目标，不表示已经具备自动同步实现：

- Host 已能显式选择 Intent 和 Software；[Zed 更新入口](../runbooks/update-zed-preview.md)更新固定版本与 hash，不负责从选定现场配置组织稳定声明。
- macOS 的 Home Manager 被组合进 nix-darwin 系统 output；整机应用还可能涉及系统设置和 Homebrew/MAS。构建通过不能证明只改了本次选中的对象。
- Darwin 与 Linux 使用不同 package set；[现有 Zed 决策](../adr/0006-zed-nightly-upstream-flake-and-cache.md)还明确区分 Preview 与 Stable。现存版本差异不构成错误；显式要求版本一致的同步需单独验证目标平台能力。
- 现有 `mw-recall` 由 `mw: recall` 触发，`mw-capture` 由 `mw: capture` 或 Recall 完成 host 工作触发；显式调用后的闭环已有实现，不要求增加普通跨项目任务的自动触发。

这些边界由具体任务中的执行方案处理，不预设新的记录类型、同步框架、部分激活框架或软件项目。
