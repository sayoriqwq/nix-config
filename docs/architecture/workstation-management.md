# 主工作站管理

本仓库以 macOS 日常使用与换机恢复为目标。维护者通过少量明确动作更新软件、保存认可的配置；换机以仓库当前内容和可取回的外部材料为起点。Nix、Homebrew 与原生应用分别承担实际有收益的职责，具体工具取舍仍按资源决定。

当前运行环境是实际状态的唯一事实来源。仓库保存维护者选定的稳定声明和输入，明确应用时写入什么；声明、generation 与现场并不天然一致。决定见 [ADR-0011](../adr/0011-declaration-led-workstation-management.md)，术语见 [CONTEXT.md](../../CONTEXT.md)。

本轮重构从已经入仓的内容继续维护，新增内容按明确需求保存，不重新盘点或补齐整台机器。未保存的临时配置修改可以被受管声明覆盖，不为保全它们增加自动捕获、快照台账或同步流程。既有安装来源也可以复审，特别是曾为更新方便而迁出的软件；分别检查安装、更新与配置应用的收益，不把历史迁入或迁出当作最终答案。

## 日常更新入口

[bin/workstation](../../bin/workstation) 复用现有 Homebrew、Nix、nh 与 Git。入口读取当前 Mac 配置的求值结果和 `flake.lock`，不增加软件注册表；配置修改后的验证与应用仍见[日常 Nix 维护](../runbooks/daily-nix-maintenance.md)。

```fish
./bin/workstation update qq
```

⬆️ 更新已声明、已安装的 QQ，也可传入其他已声明的官方 cask 全名或唯一短名。入口核实安装来源，尝试刷新官方 API 目录，预览并定向升级，最后核对安装记录并提示实际功能验收。

```fish
./bin/workstation update nix
```

🧰 只更新 `nixpkgs-darwin`，构建并展示 Mac 候选，确认后应用已审阅的产物；实际功能验收通过后，自动本地提交本次 lock 变化。

这里的 `nix` 是 Mac 工具集更新入口，不是只更新 Nix/Lix 程序。它不默认更新 Linux 输入、nix-darwin、Home Manager 或固定来源。包集更新可能影响多个软件和依赖，不能解释为单软件更新。

| 环节 | Homebrew cask | Nix 工具集 |
| --- | --- | --- |
| 对象 | 从当前 Mac 配置求值得到官方 cask 声明，核实已安装及来源；未声明或未安装时停止 | 固定目标 `macbook`、输入 `nixpkgs-darwin`；已有 lock 或非文档的受跟踪改动先处理归属 |
| 准备 | 尝试刷新官方 API 后再次检查来源；预览定向升级，不自动安装缺失应用 | 更新输入后校验只有目标叶输入变化，由 nh 构建并比较候选，系统尚未应用 |
| 应用 | 不强制重装、不清理；依赖超出单软件范围时列出并停止 | 展示 lock 和包差异，确认整份配置影响；由 nh 引用固定构建产物应用，源码或 lock 中途改变即停止 |
| 收尾 | 核对安装记录，再确认应用启动和日常功能；无定义变化，不生成提交 | 核对运行产物，再确认实际功能；只提交本次 `flake.lock`，不自动推送 |

单软件路径使用 Homebrew 的官方 API 刷新机制，禁用全局自动更新，不调用可能迁移其他已装软件的 `brew update`。网络失败时 Homebrew 可能沿用缓存，工具提示会保留；“当前目录无更新”不保证远端已经没有新版。第一版只支持官方 cask 与 API 安装模式，第三方 tap、非 API 模式或其他软件依赖会停止；它们的目录维护应作为单独动作处理。目标更新仍可能需要退出应用，未知对象不自动推断 Nix 来源。

Nix 路径允许现存文档差异并保留已暂存内容；已有配置或 lock 差异必须先提交或隔离。构建前、构建后、确认后和提交前检查候选归属。nh 4.4.2 的 Darwin 后端不直接接受 Store installable，入口通过固定 Store 引用表达式让 nh 应用刚才的产物，不重新选择或构建另一份仓库配置。

包差异不能覆盖所有系统设置、可写文件、Homebrew 和登录任务的变化，所以整机应用前保留一次范围确认。只有明确想保留的现场修改才先保存到声明；不增加逐字段比对、自动捕获或私有快照台账。

更新成功应用并完成实际功能验收后，自动本地提交本次 `flake.lock` 变化，不混入已有差异或已暂存的其他工作，不推送。失败、取消或未验收时保留差异、不生成成功提交；无变化时不制造空提交。提交失败单独报告，已成功的应用不因此变成“未发生”。

### 验证与失败处理

脚本分别报告 lock、构建、应用、功能验收和提交状态；cask 路径分别报告安装和功能验收。退出码 `0` 表示完成或无需更新，`1` 表示失败或保护条件停止，`2` 表示取消或未通过功能验收。中断保留已产生的差异；激活失败可能已有部分写入，不能直接视为系统没变。

模拟测试覆盖定向更新、范围拒绝、构建失败、取消、候选变化、验收失败和独立提交。它们不证明实际 QQ 更新、工具功能或登录行为；真实验收仍需更新后的现场操作。恢复沿用已有代际与应用自身机制，见[恢复手册](../runbooks/restore-macos-environment.md)。

## 日常使用与保存

可以先在 Mac 安装、试用和调整，再把认可且适合复用的设置、快捷键、任务保存为 Nix 版本。选择一个 Software 不等于接管它的全部配置和数据。每项声明必须按实际机制区分安装需求、包版本、持续管理字段和仅初始化材料。

Ghostty 与 VS Code 的 Mac 安装需求分别由现有 Homebrew cask `ghostty`、`visual-studio-code` 声明保存，应用仍位于 `/Applications/Ghostty.app` 和 `/Applications/Visual Studio Code.app`，通过原生渠道独立更新；当前 Homebrew 激活不升级已有包。Home Manager 的配置与 CLI 接线保持原有职责。

WezTerm 是低频使用的兼容终端，保留 Nix 安装与现有社区配置模块，版本由 `flake.lock` 中的 `nixpkgs-darwin` 输入锁定，关闭应用更新提示，不单独追新。更新该包集时，WezTerm 仍可能随候选一起变化；是否接受通过同一份候选差异判断。

LocalSend 的 Mac 安装和升级由 Homebrew cask `localsend` 负责；Linux 保留 Nix 包与既有防火墙规则。Pages、Keynote、Numbers、GarageBand 按维护者选择移出安装声明，交由系统或 App Store 处理，缺失不形成补录任务。当前 Homebrew `cleanup = "none"`，移除声明不会自动卸载现场应用。

Discord、IINA、MonitorControl、Mos、Upscayl 和 xbar 的 Mac 安装需求由 Homebrew cask 保存，日常沿用应用自身更新机制；IINA 的 CLI 由 cask 提供。Home Manager 不再安装这些应用，Mos 的登录启动移入下述集中声明。应用偏好、插件、账号和 macOS 权限仍由产品与系统管理。

Obsidian 的 Mac 安装需求由 Homebrew cask `obsidian` 保存，日常更新由应用处理，Electron 安装器通过 Homebrew 按需升级。官方 CLI 由 cask 提供，使用前在应用内开启命令行界面；Home Manager 不再提供旧的图形程序链接。笔记库、插件、主题、偏好与账号由 Obsidian 管理，Linux 继续使用 Nix 包。

长期软件优先使用社区 Nix 模块和 nh，允许合理版本滞后；实际阻碍可以支持原生迁移。迁出后删除无人使用的固定包与更新器，保留仍有用途的配置和集成。当前 Lix、nix-darwin、集成 Home Manager 与 Darwin rolling/Linux release 都可按真实需求复审，不预设永久绑定。

日常入口见[日常 Nix 维护](../runbooks/daily-nix-maintenance.md)。按实际操作需要增加包装命令，复用 Git/Nix/nh，减少重复输入；不另造声明或恢复系统。

## 登录启动

2026-10-13 已确定：普通 GUI 应用的受管登录启动统一使用 Home Manager 的标准 `launchd.agents`，集中保存选定名单。同一应用只保留一个负责登录时打开它的入口，迁移时撤销重复的原生登录登记；应用的必要后台 helper、更新器和网络扩展继续按产品机制处理。

受管名单见 [hosts/macbook/login-items.nix](../../hosts/macbook/login-items.nix)。按维护者要求，纳入本机所有已启用且可用标准 Home Manager 接管的普通 GUI 登录启动，包括独立安装和 Setapp 应用；安装来源不限制登录启动归属。此文件是受管登录启动的唯一声明，迁移时撤销对应原生入口，后续名单在这里维护。应用安装、订阅和偏好仍按各自机制处理。

当前包含 14 个普通应用或菜单栏启动目标。普通任务通过 `open -g` 打开指定应用，不因用户手动退出而重新拉起；Timing 使用原本的 `TimingHelper.app`，Tailscale 只接管打开主应用的登录跳板，保留网络扩展。另将自行部署的 NuPhy Key Probe 常驻任务纳入同一文件，沿用原 label、参数、日志位置和 `KeepAlive=true`，不改变它的常驻服务语义。

新增或修改任务后的激活可能立即启动应用或重启常驻任务；移除普通 GUI 声明不代表退出已运行的应用。此实现不会持续同步所有厂商开关或阻止应用自行重新登记；若发现重复原生入口，应按这份声明纠正，不把原生开关当作第二份期望配置。

集中声明已经入仓；现场切换仍须撤销重复原生登记，并在下一次实际登录后验收。Setapp 的 XPC 服务、更新器、设备驱动、网盘服务等独立后台任务继续由产品维护；它们并非另一个“打开主应用”的清单，不能用一次 `open` 替代。迁移与恢复步骤见[恢复手册](../runbooks/restore-macos-environment.md)；方案比较与验收依据见[登录启动研究](../research/macos-login-startup-management.md)。

## 写入边界与偏移

外部可写配置默认不建立自有同步或合并引擎。按资源选择仅在缺失时初始化、每次激活整份覆盖，或使用社区模块合并声明。具体机制、额外字段处理和删除语义写在最近的 Software 或 runbook，不建立全局矩阵。

偏移只涉及已声明且持续管理的字段。用户新增的未声明设置、账号、会话和数据不是声明缺陷，也不形成自动捕获任务。应用会重新执行所选配置的激活动作；只有明确想保留的现场修改才先保存到声明，其余未保存的受管字段修改可以被覆盖。常规应用不增加逐字段比对或强制私有备份；发现差异本身不授权整机激活。

Zed 的 Mac 安装需求由 Homebrew cask `zed@preview` 保存，Preview 应用原生更新；CLI 直接使用 `zed-preview`，`z` 快捷与默认编辑器跟随该名称。配置使用 Home Manager 的可写合并，声明字段在每次激活时重新应用，额外字段保留；删除声明不会删除现场遗留字段。具体写入限制与处理方式见 [Zed 手册](../runbooks/update-zed-preview.md)。

VS Code 的 Mac 默认用户 `settings.json` 使用持续整份覆盖：每次激活写入仓库基线，文件仍可直接编辑；该文件内未保存的修改和额外字段会被覆盖。基线使用 `update.mode = default`，扩展、账号、keybindings 与其他 profiles 不自动纳管。具体范围与验收见 [macOS 环境恢复与回滚](../runbooks/restore-macos-environment.md)。

## 选择复用

维护者选择软件、配置和目标机器，验证目标实际行为。重点是相同的使用意图，允许平台适配和软件版本差异；精确版本一致只在明确要求时核实。

macOS 的 Home Manager 集成在 nix-darwin output 中，整机应用可能同时涉及系统设置和 Homebrew/MAS。修改单个 Software 不证明激活只影响该软件，也不授权整机动作。沿用 [AGENTS.md](../../AGENTS.md) 的目标、动作、停止条件与恢复边界。

每台机器的登录态、用户内容和应用数据独立；数据同步属于单独需求，优先采用软件现有能力。不能保留未选中状态时，应说明限制并调整方案。

## 私有记录与恢复

Macwarden 独立保存维护者选定的私有现场证据和历史，其模型、Skills、存储定位与触发合同由该项目维护。本仓库不复制这些实现，也不增加普通工作的自动捕获或跨 Agent 管理规则。历史记录只能证明对应时间与范围，不能取代当前读回。

配置恢复使用已保存且可获取的声明与产物；未保存的现场变化不在保证内。Git 回退与运行环境回滚是不同动作，generation 不保证撤销 defaults、外部安装器和可写配置的全部副作用。应用数据依赖自己的备份与恢复流程，不增加高于 Nix 的恢复编排层。
