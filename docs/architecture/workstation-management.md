# 主工作站管理

本仓库是个人 macOS 托管的统一入口。先解决主工作站的日常使用，再按维护者的实际选择复用到 nixbox 或 server；术语定义以 [CONTEXT.md](../../CONTEXT.md) 为准，声明结构与主机拓扑见[整体架构](overview.md)。

## 稳定声明与日常使用

nix-config 保存维护者认可的软件版本与稳定配置。安装、更新、手动调整和软件自更新可以使实际状态产生正常偏移；日常变化无需立即回写稳定基线，也不自动触发其他机器的更新。

允许偏移不改变已有安装方式的技术约束。例如 Store 中的程序不能直接改写自身，固定版本仍按对应 Software owner 的更新入口处理；托管约定本身不迁移安装来源或开启自更新。执行 Agent 根据现场路径、版本、配置和依赖判断当前可行的操作，负责影响判断、必要确认、结果回读及记录。

## 选择同步

同步由维护者明确选择软件、精确版本、配置与目标机器。执行 Agent 从 Mac 现场确认被选中的内容，保存认可的稳定声明，并验证目标上的实际结果：

- 选中软件的版本一致；必要的平台配置适配保留使用偏好，不能以更换版本冒充适配。
- 目标上未选中的状态及偏移保持原样；同步后仍允许新的日常偏移。
- 普通用户文件、应用数据、登录态和凭据不随软件/config 同步迁移。

目标平台若不能提供选定版本，或当前操作无法保留未选中状态，执行 Agent 应说明限制并调整执行办法；扩大选择范围或改选版本由维护者决定。只修改一个 Software 的声明再应用整机 output，不足以证明满足这些要求。

## 私有记录与跨项目使用

个人实际状态和变化证据使用 Macwarden 的现有 Observation / Transition 模型保存。主 checkout 内的 `.macwarden/` 是被 Git 忽略的私有 authority；它不进入 Flake、公开提交或其他 worktree。Macwarden 工具源码与 Skills 继续由独立工具项目维护。

Macwarden setup 保存该 authority 的绝对路径，因此从其他 cwd 执行也访问同一份记录；使用时通过 `macwarden path` 核实目标，不依当前项目目录另建记录库。模型、CLI 和 Skill 合同以 Macwarden 工具项目自身文档为准，本仓库不复制其实现。

Agent 无论在哪个项目工作，对本机长期环境造成的变化都应围绕有用的主题留下证据，包括已核实的位置、用途和运行依赖。普通项目依赖仍归项目管理；手工操作在维护者要求时捕获。记录主题围绕可以持续观察的问题选择，不为无有用主题的行政整理硬造 Scope。

日常操作由执行 Agent 负责，现有 Recall/Capture Skills 承担查历史、现场回读、操作后验证和写入记录的组合。这里不增加常驻监听、自动追赶声明或另一套审批流程；具体执行约束见 [AGENTS.md](../../AGENTS.md)。

## 历史与恢复

已有状态的补录由维护者安排采用哪些原始流程、何时进行、覆盖什么。authority 尚未有记录不构成缺陷，也不形成自动盘点任务。

原始流程中的可信操作和前后回读可以支持历史 Transition；本次现场检查只证明本次状态。没有可靠 Before 时保存独立 Observation，保留历史未知项；当前记录不替换原始历史，不从记录顺序推断机器现状。

恢复以实际留存的证据和材料为限。已记录原因、路径和变化，不代表已经保存配置全文、软件产物或用户数据；历史 Change 也不是可直接重放的恢复程序。执行 Agent 结合现有材料与新的现场事实确定可恢复的部分及未知项。

## 当前能力边界

以上约定确定使用目标，不表示已经具备自动同步实现：

- Host 已能显式选择 Intent 和 Software；[Zed 更新入口](../runbooks/update-zed-preview.md)更新固定版本与 hash，不负责从选定现场配置组织稳定声明。
- macOS 的 Home Manager 被组合进 nix-darwin 系统 output；整机应用还可能涉及系统设置和 Homebrew/MAS。构建通过不能证明只改了本次选中的对象。
- Darwin 与 Linux 使用不同 package set；[现有 Zed 决策](../adr/0006-zed-nightly-upstream-flake-and-cache.md)还明确区分 Preview 与 Stable。现存版本差异不构成错误；显式要求版本一致的同步需单独验证目标平台能力。
- 现有 `mw-recall` 由 `mw: recall` 触发，`mw-capture` 由 `mw: capture` 或 Recall 完成 host 工作触发；显式调用后的闭环已有实现，普通跨项目任务的自动触发尚未接通。

这些边界由具体任务中的执行方案处理，不预设新的记录类型、同步框架、部分激活框架或软件项目。
