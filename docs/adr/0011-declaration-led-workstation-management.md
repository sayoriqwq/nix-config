# ADR-0011：保存所选声明，按资源明确写入边界

状态：已接受；2026-09-14 修订原决定；2026-10-03 简化日常配置应用的前置步骤，并将 Mac 的 VS Code 默认用户设置改为持续整份覆盖；2026-10-13 确定 Home Manager 统一管理普通 GUI 登录启动，更新成功应用并验收后自动本地提交。

当前运行环境是机器实际状态的唯一事实来源。Nix 声明和 lock 保存维护者选定的配置、输入与主机选择，决定应用时实际写入什么；它们不证明现场已经一致，也不因选择某个软件而拥有其全部状态。

主工作站可以先试用和调整，再将希望长期保留、跨主机复用的内容保存为 Nix 版本。复用重点是设置、快捷键、任务等使用体验，允许平台差异和独立软件版本。偏移只涉及已声明且由应用机制持续管理的字段；额外设置不是待补录债务。日常应用按所选写入机制执行，明确想保留的现场修改先保存到声明；未保存的临时配置修改可以被覆盖，不强制逐字段比对或建立私有备份。已有入仓内容继续维护，新增内容按需求保存，不开展全机补录。

长期软件优先采用社区 Nix 模块与 nh，接受合理版本滞后；实际功能或维护阻碍可以支持原生迁移。已经迁出的包不保留无人使用的固定包或更新器。Lix、nix-darwin、集成 Home Manager 以及当前平台输入节奏是当前选择，不是永久绑定。

外部可写配置默认不建立自有同步或合并引擎。按资源选择仅初始化、持续管理或社区可写合并，并在软件附近说明写入范围和恢复限制。Zed 明确选择 Home Manager 的持续可写合并：每次激活重新应用声明字段，同时保留额外字段；具体限制见 ADR-0006 和对应手册。VS Code 的 Mac 默认用户 `settings.json` 则在每次激活时按仓库基线整份覆盖并保持可写，文件内额外字段不保留；希望保留的修改先保存到声明。原生应用安装与更新归属不变，扩展、账号、keybindings 和其他 profiles 保持外部。

稳定期以 nh 和按实际需要增加的包装命令维护，沿用 Git/Nix 的声明和回滚机制。试用期的 Issue/PR 协作及逐级流程关卡退役，历史留在 Git；AGENTS.md 改为单份中文维护约定，不重复源码可读的事实。Macwarden 独立维护私有记录、模型与 Skills，本仓库不接管跨 Agent 治理或复制其合同。软件数据和备份保持外部。

普通 GUI 应用的受管登录启动统一交给 Home Manager 的标准 `launchd.agents`，集中保存本机可接管的全部现有登录启动，不限安装来源；同一应用只保留一个入口，这份声明是期望登录行为的唯一来源。自行部署的常驻启动任务也使用同一文件中的标准 agent，保留各自运行语义；必要的产品后台服务保持其原有机制。选择此方案是为了复用现有模块和仓库恢复能力，接受新增或修改任务后的激活可能立即启动应用或重启任务，不引入独立启动器，也不承诺同步全部应用的原生开关。

日常更新入口在成功应用并完成实际功能验收后，自动本地提交本次 `flake.lock` 变化，不推送、不混入无关改动。失败、取消或未验收时保留差异，无变化时不生成空提交。入口与集中登录声明已实现，使用与验收边界见主工作站管理文档；仓库实现不代表现场登录项已经切换或真实更新已经验收。

本修订取代 2026-09-13 将全部受管软件的日常状态维护默认收束到声明的表述。代价是恢复保证必须逐项说明，尚未保存的现场修改无法靠 Git/Nix 重建。真实机器激活仍遵循 AGENTS.md；决定和构建均不代表已经执行。

管理约定见[主工作站管理](../architecture/workstation-management.md)。
